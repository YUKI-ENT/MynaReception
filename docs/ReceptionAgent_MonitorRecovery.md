# 監視フォルダーのアクセス障害と自動復帰

「監視開始」または「アプリ起動時に監視を開始する」で開始した監視は、ネットワーク切断・共有フォルダーの未接続・アクセス拒否の場合も終了しません。メイン画面に「フォルダーアクセス待ち（5秒ごとに自動再試行）」と対象フォルダーを表示し、バックグラウンドで再確認します。アクセスできるようになると同じ監視処理が自動で続行します。無人運転では起動時の監視開始をONにしてください。

確認対象はface出力、trash、iCall request/response。自動照会番号登録がONの場合はOQS req/resも確認します。必要なフォルダーにアクセスできるまでは、新しいXMLの取込・受付処理・自動照会番号登録・再検証・Kiosk自動受付を待機します。確認のためにフォルダーを新規作成することはありません。

フォルダー障害では確認ダイアログを表示しません。設定不正やローカル履歴の障害など、監視を継続できない問題は従来どおり報告します。監視開始時のエクスプローラー起動もresponseフォルダーの復旧を待ち、その起動失敗で確認ダイアログを出すことはありません。

取込履歴や送信済み要求をリセットせず、同じXML・requestIdを使って続行します。実行中の照会番号登録や発券の結果が不明な場合は、既存の重複防止動作を維持します。直接出力のreceipt.txt配送は従来どおり再試行を続けます。

「監視停止」を押すかアプリを終了すると、復旧待ちも停止します。明示的に停止した後は自動で監視を開始しません。ネットワークアクセス自体の完了時間はWindowsの共有接続タイムアウトに依存するため、5秒は各確認処理の終了後の待機時間です。アクセス確認はUIスレッドでは実行しません。

処理ログには`monitor_folder_unavailable`と`monitor_folders_recovered`を記録します。同じフォルダーの待機状態を毎回記録せず、状態変化時に記録します。
