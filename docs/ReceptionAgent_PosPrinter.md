# ReceptionAgent POSプリンタ

## 設定と操作

1. WindowsにUSBプリンタを登録し、テスト印刷・カットを確認する（例: `POS-80C`）。
2. ReceptionAgentの「設定」→「POSプリンタ設定」で出力を有効にし、プリンタ、医院名、80mm／58mmを選ぶ。初期値は出力OFF、`POS-80C`、80mm。
3. 患者用とスタッフ用のタブで各行の文面・フォント・サイズ・太字・後の余白・配置・枠囲いを編集する。「見本・テスト印刷」でプレビューやサンプル印刷ができる。「適用」後、親の設定画面で「保存」する。
4. 一覧の患者を選び「POS発券（2枚）」でプレビューを開き、印刷する。患者用→スタッフ用の順に各1ページを送信する。再操作は再印刷になる。

窓口発券の対象は有効なXML氏名を取得でき、患者・予約照会が終了した受付（エラー・タイムアウトによる再試行待ちを含む）。診察券番号や予約番号がなくても発券できる。同名XMLの競合や本人照合不一致、自動発券・Kiosk自動処理中は手動発券を無効にする。Kioskの発券対象条件は従来どおり再診・予約ありなどの確認済み受付に限定する。日付時刻にはXML取得日時（Kioskでは受付開始日時）を使用する。

既定のWindowsプリンタは使用せず、設定したプリンタ名を使用する。手動印刷ダイアログでは別のプリンタへ変更できる。Kiosk自動発券は自動受付設定のプリンタ名を使う。

メイン画面の「受付モード」でKioskあり／なしを選択する。初期値はKioskあり。変更は即時保存され、監視を再起動せず次に取得するXMLから適用される。以前のモードで取得したXMLや過去の履歴を一斉に発券することはない。

**Kioskなし**では、POS出力ONなら患者・予約照会が終了した受付を自動発券する。初診・予約なしも対象。照会エラーやタイムアウトで再試行待ちになった場合も、XML氏名を取得できていれば発券する。取得できない診察券番号・予約番号は空欄にする。通常の検索待ちでは発券しない。XML不正で氏名がない場合、同名XMLの内容競合、本人照合不一致は自動発券しない。来院確認・連携の自動操作はこのモードでは追加しない。

**Kioskあり**の自動発券は、別途「Kiosk自動発券設定」で自動発券をONにしてプリンタを指定する。POS出力ONだけではKiosk自動発券されない。用紙幅・医院名・文面は共通設定を使う。既存の対象判定、二重発券防止、結果不明時に自動再発券しない動作を維持する。Kioskなしを選択している間、Kiosk受付とその自動発券は待機する。来院確認・連携は下記の共通スイッチで指定する。

## 自動来院確認・自動連携（Kioskモード共通）

メイン画面上部の「自動来院確認」「自動連携」で個別に指定する。初期値は両方OFF。変更時に即保存し、監視の再起動なしに、これから患者ID・予約番号が確定する受付へ適用する。完了済みの履歴へ遡って操作しない。予約確定時に保存した操作計画は、途中でチェックを変更しても完了まで同じ要求ID・連携方式で継続する。

当日のface XMLで患者を特定し、iCallから予約番号と予約患者名を確認できた場合に実行する。Kioskの有無、誕生日・発熱等の質問回答や自動発券条件には依存しない。両方ONなら来院確認→連携の順。予約なし、患者照合不成立、当日以外、再検証のカルテ番号不一致、ファイル競合は自動操作しない。この自動来院確認・連携処理ではダミー枠作成や患者割当は行わない。別途「予約なし」モード／「予約なし枠割当」ボタンで、診察券番号が確定した再診のみ既存ダミー枠への割当を指示できる。

連携はReceptionAgent設定の「iCall連携／直接出力」に従う。直接出力は既存のreceipt.txt配送を使用し、ファイル出力受付とDynamics取込完了を区別する。「連携しない」では自動連携を実行しない。来院確認・iCall連携にはiCallManager側の「実操作を有効化」が必要。

Kioskの新しい受付はメイン画面の共通スイッチを使い、旧Kiosk設定のAutoArrival/AutoLinkは使用しない。更新前に保存された実行中のKiosk操作は引き続き既存の要求IDで結果を確認する。Kiosk自動発券は共通操作の完了を待ち、記録済みの来院確認・連携を重複要求しない。

操作要求は送信前にDBへ保存する。タイムアウト時は同じ要求IDで応答を再確認し、別要求として作り直さない。iCallで失敗・不整合が返った場合は要確認で停止し、次の自動操作へ進まない。処理ログのautomatic_operation_queuedで操作の種類と取込IDを確認できる。

Kioskなしの発券状態は一覧の「発券」とダブルクリック詳細に表示する。送信直前に履歴を保存し、成功後は「送信済み」、失敗・中断結果不明は「要確認」とする。アプリの再起動でも自動再発券しない。空欄で発券した後に番号が確定しても、自動では再発券しない。職員が用紙とキューを確認し、必要なら手動発券する。モードをKioskありに変更した場合、Kioskなしで取得した未発券XMLの自動発券は待機する。

## 文面

差し込み項目: `{医院名}`、`{日付時刻}`、`{予約番号}`、`{番号}`、`{名前}`、`{フリガナ}`、`{マイナ氏名}`、`{マイナフリガナ}`、`{診察券番号}`。`{番号}`と`{予約番号}`は同じ予約番号。診察券番号にはカルテ番号を使用し、先頭のゼロを保持する。各行の固定文字も自由に編集できる。

`{名前}`と`{フリガナ}`はマイナXMLの漢字氏名・氏名カナを優先する。XML側の値がない場合は従来の氏名情報に補完する（手動発券の氏名はカルテ→iCall予約、Kioskは確認済み氏名。フリガナはカルテ）。`{マイナ氏名}`と`{マイナフリガナ}`はXML由来の値だけを出力し、取得できなければ印刷を止めて通知する。他の取得元へ黙って置き換えない。

各行にフォント（利用PCにインストールされたフォント）、サイズ6～48pt、太字、行の後の余白0～20mm、左寄せ／中央寄せ／右寄せを指定できる。配置の初期値は中央寄せ。余白はその項目と次の項目の間の追加余白で、長い氏名が折り返された項目内の行間はフォントの標準行間を使用する。空行、最下行での行追加、行選択＋Deleteでの削除、「行を上へ／下へ」の並べ替えに対応する。既存設定に書式がなければ従来のフォント・サイズ・余白で読み込む。

「スタッフ用のフォント・文字サイズを患者用に合わせる」は初期値ON。同じ項目（名前・フリガナ・日付時刻・番号・診察券番号など）の患者用フォントとサイズを使う。患者用に対応行がない通常の行は、患者用の最初の通常行に合わせる。スタッフ用の配置・太字・余白・枠囲いは個別設定を維持する。OFFにするとスタッフ用のフォント・サイズを個別に編集できる。

スタッフ用の「スタッフにお渡し下さい」は初期状態で枠囲いする。文面欄を「受付スタッフへお渡しください」などに変更しても、枠囲いをONにしていれば枠を維持する。各行の「枠囲い」で他の項目も囲める。用紙長の計算には枠内の余白を含め、58mm・80mmともに折り返しに対応する。

新規設定の患者用の初期文面は医院名、日付時刻、予約番号、名前、フリガナ、診察券番号。スタッフ用は「スタッフにお渡し下さい」、番号、日付時刻、名前、フリガナ、診察券番号。長い氏名は用紙幅に合わせて折り返す。保存済みの文面には自動で行を追加せず、フリガナを出すには任意の行に`{フリガナ}`または`{マイナフリガナ}`を追加する。

## 用紙とカット

Windowsドライバで印刷する。用紙幅はアプリとドライバの両方で合わせる。「1枚ずつ別の印刷ジョブで送る」は初期値ONで、患者用とスタッフ用を各1ページの別文書として送る。ドライバが **AfterDocument = Cut（文書終了時にカット）** の場合は、この設定をONにする。保存済み設定に項目がない場合もONで読み込む。OFFなら従来どおり1文書2ページで送るため、各用紙を切るにはドライバのページごとのカット設定が必要。

見本・手動印刷ダイアログの詳細設定は、実際の印刷にも引き継ぐ。自動発券は指定したWindowsプリンタの既定の印刷設定を使用する。アプリからカットコマンドを直接送るものではないので、ドライバの自動カット設定は必要。文面に応じた用紙長を指定し、ドライバが任意用紙サイズを受け付けない場合や印刷領域に収まらない場合はエラーになる。

USB機器の実印刷とカットは利用PCで確認する必要がある。キューへの送信成功は物理的な印刷完了を意味しない。途中失敗時には一方の用紙だけ出ている可能性があるため、キューと用紙を確認してから手動で再操作する。

## その他の変更

- 左上の「XML監視」タイルで監視をON/OFFする。初期値OFF。状態は即時保存し、次回起動時に復元する。旧「アプリ起動時に監視を開始する」の設定値も引き継ぐ。ON時は通常の監視開始と同じ設定検証を実行する。
- 設定画面のフォルダー入力はフォーム幅に合わせ、右端の「参照」を確保する。
- 一覧はファイル名とそれ以降の日時・再検証列を非表示にする。これらは行のダブルクリックで確認できる。
