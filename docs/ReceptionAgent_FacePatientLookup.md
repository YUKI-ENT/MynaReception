# face XMLからの患者ID検索（第1段階）

照会番号Bulk登録の拡張は保留。本文は患者照合ルールと手動テストの説明です。自動取込・SQLite保存・予約APIの操作は [face XML自動取込](ReceptionAgent_FaceCapture.md) を参照してください。

## 操作

1. 同じPCのDynamicsで「患者マスター」フォームを開く。
2. ReceptionAgentの「設定」でface XMLフォルダーと文字コード（UTF-8／Shift_JIS＝CP932）を指定。
3. メイン画面の「手動患者検索（テスト）」を開き、「face XMLを選択・患者検索」で `OQSsiquc01res_face_*.xml` を選択。
4. フリガナ・生年月日・一致した患者ID／内部カルテ番号を確認。

face XMLフォルダーは自動監視先と手動選択時の開始フォルダーとして使用します。OQS Bulkのフォルダーは空欄でもface検索の設定を保存できます。

## XML

構造はユーザー提供サンプルに対応。

- MessageHeader/MedicalInstitutionCode
- MessageHeader/SegmentOfResult = 1
- MessageBody/ProcessingResultStatus = 1
- MessageBody/ResultList/ResultOfQualificationConfirmation/NameKana
- 同階層のBirthdate（西暦 yyyyMMdd）

InsuredNameは保険の名義人なので患者照合には使いません。ReferenceNumberの有無にかかわらず、今回の操作はNameKanaとBirthdateで照合します。結果ノードが複数あるXMLは先頭を選ばずエラーにします。医療機関コードが接続先Dynamicsと違う場合も停止します。

設定に従って厳密に復号し、XML宣言との不一致や文字化けを黙って補正しません。UTF-8のBOMは対応します。DTD・外部実体は禁止、サイズ上限は4MiBです。ファイルはFileShare.ReadWrite | Deleteで読み取り、300ms間隔で内容が同一になることを確認します。元ファイルは削除・移動・書換しません。

## Dynamics検索

患者マスターテーブルからカルテ番号・氏名・フリガナ・年号・生年・月・日を読取専用DAOスナップショットで取得します。年号はユーザー確認済みの日本語（昭和、平成、令和等）。.NETのJapaneseCalendarで西暦へ変換し、元号の開始／終了日も検証します。西暦表記にも対応。数値年号コードは推測しません。

最初に月・日と生年（対象日付の和暦年または西暦年）で絞り、メモリ内でフリガナと年月日を完全照合します。フリガナはUnicode NFKC、空白除去、ひらがな→カタカナ変換で揃えます。漢字氏名や保険情報による曖昧検索は行いません。候補数上限を超えた場合は切り捨てて一意判定せず、検索を停止します。

内部カルテ番号を10で整数除算した患者IDで候補をまとめます。同じ患者IDの複数枝番は1人として扱い、内部カルテ番号は一覧表示します。氏名カナ・生年月日の候補が複数患者IDに分かれた場合だけ、下記の保険情報による追加照合を行います。主保険チェックでは絞らず、候補内の各カルテ枝番を確認します。

- 0患者ID：一致なし。後続処理なし。
- 1患者ID：患者ID取得完了を表示。自動取込では予約番号取得へ進みます。
- 2患者ID以上：保険情報で追加照合。1患者IDに絞れれば一致したカルテ番号を表示し、絞れなければ「特定できず」の確認メッセージと元の候補一覧を表示。

手動テストの患者情報は画面上だけで使用します。自動取込はSQLiteへ保存します。新しい検索開始時には前回結果をクリアします。切り取られた生年月日などの匿名化サンプルは実患者として検索せず入力エラーになります。

## 複数候補の保険情報照合

XMLの同じResultOfQualificationConfirmationから、InsurerNumber・InsuredCardSymbol・InsuredIdentificationNumber・InsuredBranchNumberを取得します。Dynamicsでは患者保険マスターの保険者番号・記号・番号・枝番を、氏名カナと生年月日が一致した候補カルテ番号だけについてCOMで読み取ります。

4項目は同一レコード内で一致する必要があります。全角・半角と前後の空白を揃えますが、番号の先頭ゼロは除去しません。既知の1桁枝番は2桁へ揃え、空欄を00に補完しません。保険者番号・番号・枝番がXMLに欠けている場合は特定できずとします。記号なしの保険はXML・DBとも記号が空欄の場合に一致とします。

- 一致する患者IDが1つ：その患者と一致したカルテ番号を採用。「保険情報の4項目一致で特定」と表示。
- 一致する患者IDが0または複数：特定できず。元の候補を確認用に表示し、確認メッセージを出す。
- 同じ患者ID内の複数枝番が一致：患者は1人として扱い、一致枝番を一覧表示。
- 氏名カナ・生年月日で最初から一意：これまでどおり採用し、保険情報の追加取得は行わない。

保険変更等で一致しないことは別人の断定には使いません。自動取込では保険情報と検索結果をSQLiteへ保存し、予約取得へ進みます。受付転送は未接続です。
