# ReceptionAgent Kiosk Web（職員テスト用）

ReceptionAgent内でASP.NET CoreのWebサーバーを起動し、HTML/CSS/JavaScriptのKiosk画面を配信します。現在は同一PC専用で、`http://127.0.0.1:5180/` が初期URLです。Agent終了でWebサーバーも終了します。iCallManagerとの通信は従来のファイルAPIを維持しています。

通常のフレームワーク依存ビルドを実機へ配置する場合、従来の.NET 10 Desktop Runtimeに加えてASP.NET Core 10 Runtimeが必要です。開発PCでは参照・HTTP起動を確認しています。配布PCのランタイムは別途確認してください。

## 試し方

1. 新しいReceptionAgentを起動します。Webサーバーは自動起動します。
2. 通常の設定を確認して「監視開始」を押します。監視停止中はKioskからセッションを開始できません。
3. メイン画面の「Kioskコンソール」を開き、「Kiosk画面を開く」を押します。
4. 「受付を開始する」でセッションを作成し、直ちに顔認証カードリーダーを操作します。カード操作前に開始ボタンを押してください。
5. 資格確認を終えたら「次へ」で誕生月日（年・氏名入力なし）、発熱あり／なし、予約あり／なしの3項目を回答します。XML監視・カルテ検索・予約照会はこの間も独立して進みます。
6. 回答送信後、受付開始後に生成・取得されたXMLを誕生月日で照合し、既にあるカルテ・予約結果を使います。未完了ならその結果を待ちます。名前を最終画面に表示して確認できるようにしています。来院確認・連携は従来どおりAgent側で職員が行います。

Kioskから来院確認・連携・新患作成・発券を実行するAPIは設けていません。職員テスト表示は実機XMLを照合するテスト用画面であり、架空データのシミュレーションモードではありません。既存のAgentによる自動照会番号登録・WKO再検証は設定どおり動きます。

## Kioskコンソール

- 4分類ごとに案内タイトル・本文・次の動作を編集し、「案内設定を保存」で保存します。
- `StaffHelp` は職員案内、`Finish` は通常案内の表示終了を意味します。「受付完了」の実操作ではありません。初期段階ではFinishは再診・予約ありだけ設定可能です。
- 「選択案内をプレビュー」で設定文面を確認できます。
- XML待機・照会待機はそれぞれ初期60秒、15～300秒の範囲で設定可能です。
- 設定変更は新規セッションに適用し、進行中セッションは開始時の設定を保持します。
- ポート番号の変更はAgent再起動後に反映します。使用中のポートならメイン画面に起動失敗を表示します。
- セッション一覧には状態、誕生月日、発熱・予約回答、回答時刻、確定した氏名・カルテ番号・予約番号、開始日時、受付分類、表示案内、XML取込IDを表示します。選択セッションを職員側で中止できます。

発熱「あり」、患者が答えた予約有無と実際の照会結果の不一致、候補複数、患者同一性の不一致は設定した通常案内より優先して職員確認へ回します。患者の予約回答をiCallの予約結果へ上書きしません。旧APIの受診歴・診察券番号によるチェックも維持します。予約候補ありと本人確認済みを同一視しません。

## セッションとXML

セッション作成はKiosk画面の受付開始ボタンからAgentへ要求し、Agentが管理します。月日方式は全体でカード待機・照会中セッションを最大2つ、同じブラウザーは1つに制限します。旧APIの氏名・生年月日方式は従来どおり排他です。同じ要求IDの再送では同じセッションを返し、別ブラウザーから他端末のセッションを取得できません。

開始後に生成・取得したXMLを、入力した誕生月日で照合します。年・氏名はセッション照合には使用しません。生成日時が秒精度のため、開始より前と解釈される同一秒のXMLは採用しません。回答前のXMLも受付開始以降なら対象です。一致しないXMLには通常のAgent処理を続けます。一致XMLが複数なら先頭を採用せず職員確認にします。同時セッションが回答中の場合は対応付けを待ち、回答した月日が同じなら両方を職員確認へ回します。1台だけの場合は他端末待ちはありません。

1つのXMLは1セッションにしか割り当てられません。対応付けはSQLiteのUNIQUE制約で保存します。XML採用後は照会待機期限に切り替わり、分類確定で案内表示へ進みます。監視停止・時間切れは職員案内になります。

再読込みでは同じセッションへ復帰します。開始応答が失われた場合もブラウザーの識別Cookieから進行中セッションを取得できます。回答の再送は同内容なら冪等、異なる回答への変更は拒否します。未送信の回答は保存せず再読込みで消えます。表示終了・中止は外部の受付処理を取り消す意味ではありません。案内表示は60秒後に開始画面へ戻ります。入力中もXML待機期限が適用されるため、カード操作・回答に時間がかかる場合はコンソールで待機秒を延ばしてください。

誕生月日は完全な本人認証ではありません。検出できない同月日の別人や遅延生成XMLもあり得るため、当面は職員が操作順と表示された名前を確認してください。リーダー識別子による紐付けは未実装です。サーマルプリンター向けの氏名・カルテ番号・予約番号はセッションに保持しますが、印刷処理は未実装です。

## 通信・保存先

画面は埋込みリソースとして配信し、外部CDNやインターネット接続は不要です。状態はHTTPで約1秒間隔で取得します。現段階でSignalR/WebSocketは使用しません。

| API | 用途 |
|---|---|
| GET /api/health | 監視利用可否 |
| GET /api/current | 同じブラウザーの進行中セッション復旧 |
| POST /api/sessions | 回答なしで先行作成（旧方式のanswers指定も対応） |
| POST /api/sessions/{id}/answers | 誕生月日・発熱・予約有無を後から送信 |
| GET /api/sessions/{id} | 表示状態取得 |
| POST /api/sessions/{id}/cancel | 待機・案内の中止 |
| POST /api/sessions/{id}/acknowledge | 表示終了 |

患者用APIには管理設定変更・全患者一覧を公開しません。入力未完了では患者情報を返さず、照合・分類完了後に自セッションの確認用氏名だけを返します。ブラウザー識別はHttpOnly/SameSite Cookie、変更要求は専用ヘッダーと同一Originのチェックを使います。サーバーはループバックアドレスのみに待受け、外部Host・外部Originを拒否します。HTTP応答はキャッシュさせず、案内文字列はHTMLとして実行しません。

- 設定：`%LOCALAPPDATA%\ReceptionAgent\kiosk-settings.json`
- セッション：`%LOCALAPPDATA%\ReceptionAgent\Kiosk\kiosk.sqlite3`
- セッションDBには入力した患者情報を保存します。自動削除・保持期間設定はまだありません。職員コンソールは最新100件を表示します。

LANからのMiniPC接続、端末の登録・認証、HTTPS、Web版職員コンソール、診察券入力からの患者再検索、自動受付操作、発券は今後の対象です。localhost以外を設定する仕組みは現在公開していません。
