# ReceptionAgent Kiosk Web（職員テスト用）

ReceptionAgent内のWebサーバーで患者用の質問・案内を表示します。初期URLは `http://127.0.0.1:5180/`、Agent終了時にWebサーバーも終了します。現在は同一PC専用です。iCallManagerとの通信は従来のファイルAPIです。通常のフレームワーク依存ビルドでは.NET 10 Desktop RuntimeとASP.NET Core 10 Runtimeが必要です。

## 初期フロー

1. Agentの「監視開始」を押し、「Kioskコンソール」→「Kiosk画面を開く」。
2. 「マイナ受付開始」でセッションを作成してから、顔認証カードリーダーにマイナンバーカードまたはスマートフォンをセットして認証します。
3. 「資格確認が終わりました・次へ」→誕生月日→予約あり／なし→本日37.5℃以上の熱があった／なかった、と回答します。
4. 発熱ありは職員確認、予約なしは窓口での手動予約へ案内します。予約あり・発熱なしはXML照合と予約分類の結果を待ちます。
5. 再診・予約ありは通常案内、初診・予約候補は問診票や医療証を職員が確認する案内です。回答後にカードリーダー操作の案内を再表示しません。

XML監視・カルテ検索・予約照会は質問回答中も独立して進みます。Kioskから来院確認・連携・新患作成・発券を実行するAPIはありません。Agentの自動照会番号登録・WKO再検証は設定どおり動作します。印刷は未実装です。

## 質問・画面フローの編集

「Kioskコンソール」→「質問・画面フローを編集」で開始文面・質問・選択肢・変数・分岐・案内を編集します。「適用して閉じる」の後に「案内設定を保存」で保存します。キャンセルは元の設定を変更しません。保存した設定は新規セッションへ適用し、進行中のセッションは開始時の設定を保持します。

質問文や条件は `kiosk-settings.json` の `Flow` に保存します。描画用HTML/CSS/JavaScriptは埋込みリソースのままですが、文面・選択肢・遷移の変更に再ビルドは不要です。任意のJavaScriptや式の実行には対応していません。

| ページ種類 | 内容 |
|---|---|
| Card | 資格確認の説明と次へボタン |
| Birthday | 誕生月日を回答し、month / dayを設定 |
| Choice | 回答ボタンを選び、ページのVariableに選択肢のValueを設定 |
| Lookup | 必須回答を受付照会に渡し、照合・分類の結果を待つ |
| Guidance | 職員案内または通常案内でフローを終了 |

通常の編集画面はフォーム形式です。左の質問一覧から選び、右でタイトル・説明文・回答ボタンを編集します。「回答を保存する項目」と「通常の次ページ」は名前から選択できます。内部のページID・選択肢IDは自動生成します。「表示条件」は回答項目・一致する値・表示先を選択して設定します。

「質問を追加」は選択した質問の後へ「はい／いいえ」の質問を挿入し、前後の接続も変更します。「外来区分を追加」は一般診療・予防接種・特殊外来の選択肢を持つ質問を同様に追加します。初期フローには外来区分の質問を追加しないため、既存の患者画面の順序は維持します。「保存項目を追加」で任意の回答項目を作れます。回答ボタンは表の末尾から追加・Deleteで削除できます。保存する値は後続処理向けの識別値です。

内部IDや表形式の編集が必要な場合は「詳細設定」を開きます。ページIDは半角英字で始まる英数字・`_`、50文字以内、重複なしです。必須ページは通常画面から削除できません。使用中の案内を削除する場合は、先に表示先を変更してください。

「通常の次ページID」は条件に一致しない場合の移動先です。「分岐条件」は上から評価し、Variableの値がValueと一致した最初の行のNextPageIdへ進みます。「条件↑」「条件↓」で優先順を変更できます。値の比較は文字列の完全一致です。複数条件の組合せはページを段階的につないで表現します。

| 変数 | 設定元・値 |
|---|---|
| month / day | 誕生月日ページ、数字の文字列 |
| saysReserved | 予約回答、true / false |
| hasFever | 発熱回答、true / false |
| clinicClass | 外来区分の回答。追加ひな形はgeneral / vaccination / special |
| 任意の質問変数 | ChoiceのVariableに設定（例：certificate）、選択肢のValue |
| category | 照会結果専用。ReturningWithReservation / ReturningWithoutReservation / NewWithReservation / NewWithoutReservation |
| hasChart / actualReservation | 照会結果専用、true / false |

システムの照会結果変数は患者の回答から変更できません。結果変数はLookupページでの分岐に使用します。患者の予約回答と実際の予約照会は別の変数です。

例えば医療証の回答で案内を変える場合、ChoiceページのVariableを `certificate`、選択肢のValueを `yes` / `no` にします。先行ページを新しい質問につなぎ、その通常の次ページIDを `lookup` に設定します。Lookupの条件へ `certificate=yes` → 職員案内ページを追加すれば、回答で表示案内を選べます。

初期ページ `reservedDone` の本文を編集すると、「レシートを持ってお待ちください」「レシートを窓口へお持ちください」など運用に合わせて変更できます。印刷処理はないため、初期文面は「職員の案内をお待ちください」です。文面の変更で印刷や受付完了の実操作は追加されません。

「検証」はページ接続・重複ID・循環・未回答変数・必須回答の欠落を確認します。Lookup前には資格確認・誕生月日・予約回答・発熱回答が必要です。Lookup後はGuidanceへ進みます。最大50ページです。「フローを試す（架空の回答）」では回答と架空の照会結果を選んで分岐を確認できます。実機XML・予約・印刷は操作しません。

発熱、患者回答と予約照会結果の不一致、複数候補、患者同一性の問題は、通常案内より職員確認を優先します。Finishは再診・予約ありの案内表示終了で、実際の受付完了ではありません。予約候補を本人確認済みと扱いません。初期フローでは予約なしを回答段階で窓口へ回すので、職員が予約・受診歴を確認します。

## コンソールと保存

コンソールの4分類案内は旧API用です。通常の患者用画面はフロー側で編集してください。セッション一覧では氏名・カルテ番号・予約番号・誕生月日・回答・現在ページ・変数・XML取込IDを確認でき、職員側で中止できます。

XML待機・照会待機は初期60秒、15～300秒で変更できます。ポート変更はAgent再起動で反映します。表示終了や中止は外部の受付処理を取り消しません。案内表示は60秒後に開始画面へ戻ります。

- 設定：`%LOCALAPPDATA%\ReceptionAgent\kiosk-settings.json`
- セッション：`%LOCALAPPDATA%\ReceptionAgent\Kiosk\kiosk.sqlite3`

回答・変数・現在ページをページ単位で保存します。再読込みで同じページへ戻り、未送信の入力だけは消えます。同じページ回答の再送は同内容なら冪等で、変更やページ飛ばしは拒否します。開始応答が失われた場合も同じブラウザーのCookieで進行中セッションへ復帰します。セッションDBは患者情報を保存し、保持期間設定・自動削除は未実装です。コンソールは最新100件を表示します。

## XMLとの対応付け

カード操作・照会中は全体で最大2セッション、同じブラウザーは1つです。旧APIの氏名・生年月日方式は排他です。開始後に生成・取得されたXMLを誕生月日で照合し、1つのXMLは1セッションだけに割り当てます（SQLiteのUNIQUE制約）。回答前のXMLも開始以降なら対象です。

開始より前と解釈される同一秒のXMLは採用しません。一致XMLが複数なら職員確認です。同時セッションの他端末が未回答なら対応付けを待ち、同じ月日を答えた場合は両方を職員確認にします。XML採用後は照会待機期限に切り替わります。監視停止・時間切れも職員案内です。

誕生月日は完全な本人認証ではありません。当面は職員が操作順と表示氏名を確認してください。リーダー識別子による紐付けは未実装です。氏名・カルテ番号・予約番号はセッションに保持しますが、印刷は未実装です。

## APIとアクセス

| API | 用途 |
|---|---|
| GET /api/health | 監視利用可否 |
| GET /api/display | 編集した開始文面（管理APIではない） |
| GET /api/current | 同じブラウザーの進行中セッション復旧 |
| POST /api/sessions | 回答なしで開始。旧方式のanswers指定も対応 |
| POST /api/sessions/{id}/page | 現在ページの回答と次ページへの遷移 |
| POST /api/sessions/{id}/answers | 従来の誕生月日・発熱・予約有無一括送信 |
| GET /api/sessions/{id} | 表示状態と現在質問ページ |
| POST /api/sessions/{id}/cancel | 中止 |
| POST /api/sessions/{id}/acknowledge | 表示終了 |

画面は外部CDN不要で、状態は約1秒間隔で取得します。患者用APIに管理設定変更・全患者一覧は公開しません。入力未完了では患者情報を返さず、照合・分類後に自セッションの氏名だけを返します。

ブラウザー識別はHttpOnly/SameSite Cookieです。変更要求は専用ヘッダーと同一Originを確認します。サーバーはループバックアドレスだけで待受け、外部Host・Originを拒否します。HTTP応答はキャッシュさせず、案内文字列はtextContentで表示してHTMLとして実行しません。

LAN接続・端末認証・HTTPS・Web版職員コンソール・自動受付操作・自動発券は今後の対象です。localhost以外の設定は現在公開していません。

## 入力と受付結果の関係

face XMLの原本は変更しません。誕生月日でセッションに対応付け、取込IDから保存されたXMLへ参照できます。回答と現在ページはセッションDBに保存し、カルテ番号・予約番号は照合・照会結果から取得します。

バックエンドの `KioskSessions.ReceptionOutput(id, device)` は受付結果をまとめて返します。取込ID、元XMLファイル名、カルテ番号、予約番号、入力した誕生月日、予約の回答、発熱の回答、外来区分、分類・セッション状態、追加回答の一覧を含みます。未取得・未回答はnullです。外来区分を問わない既存フローでは外来区分もnullになります。

元XML＋受付結果という参照関係で、XMLに独自項目を書き込むものではありません。職員・後続処理用のバックエンド機能で、患者用HTTP APIに結果一式は公開しません。ファイルへの自動書出し・印刷・他アプリへの送信は追加していません。外来区分は患者の回答で、予約からの外来種別の検証は未実装です。

## 診察券代わりの受付済み証（58mm・手動テスト）

Kioskコンソールの「受付済み証のテスト見本…」は、プリンタ未接続でも患者用と医院控えの見本を表示できます。「見本を画像保存…」でPNGとして保存できます。実受付は履歴を選び「選択受付の受付済み証…」を開きます。

カルテ番号、確認済みの氏名、照合済み患者データの氏名カナ、予約番号、受付開始日時を表示します。予約番号は大きく印字します。保険番号や誕生日は印字しません。患者用・医院控えを各1枚、同じ印刷ジョブの2ページとして送ります。医院控えは従来の診察券の代わりにファイルホルダーへセットする用途です。

当日の再診・予約ありで、カルテ番号・予約番号と元XML取込を照合でき、フローが案内表示終了に到達した受付のみ印刷できます。中止・職員案内・発熱あり・要確認は印刷対象外です。終了した正常受付は再印刷できます。再印刷は明示的に同じ操作を行います。

Windowsプリンタドライバ経由です。「2枚を印刷…」でプリンタを選び、各1枚の送信を確認します。58×54mmの用紙サイズを指定しますが、実機ドライバの用紙対応・印刷可能幅・紙送り・ページごとのカットは接続後に確認が必要です。独自ESC/POSコマンドは送信しません。印刷キューへの送信成功は紙が出たことの保証ではありません。印刷エラー時はキューと用紙を確認してから再操作してください。

送信成功をReceptionAgentの `Logs/receipt-yyyyMMdd.jsonl` に記録します（セッションID、プリンタ、2枚送信、見本かどうか）。氏名・保険情報はログに出しません。PNGの保存先には本人情報を含みます。

iCallの来院確認・連携・印刷APIは呼びません。予約状態は変更しません。Kioskからの自動印刷と、印刷後に患者へ出す案内文の切り替えは実機テスト後の対象です。
